\# AI Use Log — Day 16 Authentication Project



\## 1. Purpose



This document records the use of AI assistance during the development and testing of the Day 16 Authentication Project.



AI was used as a learning and development assistant. The project implementation, command execution, code review, and test verification were performed interactively by the developer.



\## 2. Areas Where AI Assistance Was Used



| Area | How AI Assisted |

|---|---|

| Authentication concepts | Explained password hashing, Argon2id, authentication, and sessions in beginner-friendly language. |

| Password security | Explained the NIST password requirements and helped implement password validation and blocklist checks. |

| Session management | Explained server-side sessions, cookie flags, session revocation, and CSRF protection. |

| Login throttling | Helped design and test failed-login attempt tracking. |

| Role-based access control | Explained centralized RBAC and helped implement employee/admin authorization checks. |

| Object-level authorization | Explained IDOR vulnerabilities and helped implement record ownership checks. |

| Audit logging | Helped design audit events for registration, login, logout, access denial, and IDOR attempts. |

| Automated testing | Helped develop test cases, understand failures, and verify expected responses. |

| Documentation | Assisted in preparing the security design note, access-control matrix, IDOR log, and demo storyline. |



\## 3. Developer Responsibilities



The developer:



\- Reviewed explanations before implementing changes.

\- Executed commands and made project changes locally.

\- Inspected source files and database schemas.

\- Ran automated tests and checked their results.

\- Verified registration, login, policy retrieval, and logout manually.

\- Reviewed audit records generated by the application.

\- Maintained the project structure and documentation.



\## 4. Verification



AI-generated suggestions were not treated as proof of correctness.



Implementation behavior was checked through manual execution, database inspection, and automated tests.



The complete test suite is used as the primary repeatable verification evidence.



\## 5. Limitations



AI assistance can produce incorrect or incomplete suggestions. All security-sensitive behavior must be reviewed and tested.



The project also documents known limitations, including the small demonstration password blocklist and email-based login throttling.



\## 6. Conclusion



AI was used to support learning, implementation, debugging, testing, and documentation. The developer remained responsible for reviewing the code, executing the implementation, and verifying the results.
